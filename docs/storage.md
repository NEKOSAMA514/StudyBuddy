# 存储与恢复

本页说明哪些文件是资料、哪些可以重建，以及凭据迁移和备份的边界。安装操作见 [使用指南](usage.md)，任务与版本语义见 [契约](contracts.md)，模块设计见 [架构](architecture.md)。

## 目录与数据归属

便携包以解压目录为根：`web/` 为网页，`runtime/` 为独立 Python，`tools/` 为媒体工具，`models/` 附默认权重。原始 ZIP 不含 `data/`、`log/`、私人配置和初始化标记；首次启动才创建资料、日志与 `.runtime-ready.json` 等运行状态。便携启动器不读取开发目录 `.env`。

首次修复后路径必须固定，包括父目录名。移动后重新解压原始 ZIP，再迁移资料；升级也采用新目录，先正常停机并备份 `data/` 与 `log/`，只迁移资料、日志和可选模型，不覆盖新版环境或默认权重。凭据仍受同机同账户 DPAPI 限制。构建与开发文件边界见 [便携包说明](portable.md)。

通过本机启动脚本运行时，路径相对于实际仓库根目录确定：

| 位置 | 内容与作用 |
|---|---|
| `data/studybuddy.sqlite3` | 视频、文档、任务、依据和重点标记；SQLite 可能有 WAL／SHM 伴随文件 |
| `data/videos/<资料编号>/` | 视频原件、音频、采样图片、识别缓存、转录、生成记录及按需播放副本 |
| `data/documents/<资料编号>/` | 文档原件和 `content.json` 提取材料，以及该资料的生成检查点 |
| `data/_document_imports/<源编号>/` | 后台提取状态、解析批次、远端任务记录、OCR 与合并结果 |
| `data/downloads/` | 下载任务记录和成品；成品目录可能按标题整理，读取以任务记录为准 |
| `data/_private/` | 模型、识别、代理、MinerU 和 B 站设置／凭据，详见下表 |
| `models/` | 本地 ASR／OCR 模型文件及下载状态 |
| `log/` | 独立错误编号对应的诊断日志，实际位置以响应为准 |
| `frontend/dist/` | 正式前端构建，可以从源码重建，不是用户资料 |
| `test-results/`、实验目录 | 本机验证与实验产物，不当作正式资料读取 |

新资料目录使用 `studybuddy.sqlite3`。若目录中只有旧的 `studynote.sqlite3`，继续原位使用旧库及其 WAL／SHM，不自动改名或创建空库；两者同时存在时使用新名称的库，不合并记录。备份时保留实际使用的数据库文件名。

浏览器首次加载新版时，将旧 `studynote-`／`studynote.` 前缀的偏好及下载编号迁至 `studybuddy` 前缀；已有新键优先，迁移成功后移除旧键。该兼容只作用于当前浏览器来源，不跨端口或浏览器同步。

直接使用后端工厂时，路径来自启动设置与环境；不要在不同工作目录下无意使用另一套 `data`。项目名和可编辑资料标题都不决定文件编号或真实容器格式。

数据库和资料目录共同组成可恢复的数据，单独复制笔记正文不能恢复原件、来源映射或重点。删除资料会删除关联任务及重点；事务失败回滚与提交后的文件清理警告是不同结果。

## 私人配置与凭据

| 文件 | 磁盘格式 | 说明 |
|---|---|---|
| `_private/model-settings.json` | DPAPI 加密的完整业务 JSON | 多组 API、密钥、预算及笔记设置 |
| `_private/mineru.json` | 同一加密包装 | 独立 MinerU 凭据 |
| `_private/bilibili-session.bin` | 原有 DPAPI 二进制密文 | 保持历史登录文件兼容；持久化失败会提示本次运行有效 |
| `_private/recognition-settings.json` | 普通 JSON | 识别型号等非凭据设置 |
| `_private/network-settings.json` | 普通 JSON | 视频代理开关和地址，不支持代理认证信息 |
| 仓库根目录 `.env` | 普通文本 | 启动初值，可能含凭据；不在 DPAPI 文件加密范围内 |

前两种文件保留 `.json` 路径，外层只有 `storage_version`、`protection` 和 Base64 `ciphertext`；解密后才得到原业务结构。`protection` 为 `dpapi-user`，字节加解密、回解核对和原子保存集中在 [private_storage.py](../backend/app/util/private_storage.py)。

密文先在内存中生成并回解验证，再写入同目录独占临时文件，刷盘后原子替换目标。保存失败保留主文件，设置服务不发布候选快照，不回退明文保存。

加密使用 Windows 当前账户 DPAPI，正常启动不额外输入密码。同一账户运行的程序仍可能解密；换电脑或账户通常需要重新填写凭据。系统能力边界见 [Microsoft DPAPI 说明](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

已保存设置优先于启动初值。模型和 MinerU 显式清除后的空密钥状态也会保存，重启不会借环境变量恢复已清除密钥。读取失败与“没有配置”不同，不能用环境变量掩盖无法解密的现有配置。

## 启动迁移与失败恢复

启动装配在创建数据库、启动 Worker 和接受请求之前调用 [private_migration.py](../backend/app/settings/private_migration.py)。迁移只处理 `_private` 下的已知文件，不递归扫描用户资料。

1. 先读取并校验所有存在的模型和 MinerU 主配置，校验未通过就停止启动。
2. 逐文件加密旧明文主件、已知备份和旧临时文件。加密不改变原始业务值，备份按原始字节保留，不提升为主配置。
3. 已有密文会解密校验，但不因重复启动而重新写入。旧字段升级需要的备份也加密保存。
4. 中途失败停止启动；已完成的密文和尚未处理的原文件都保留，下次可接续。

已知历史名称包括模型／MinerU 的 rollback-backup、`.json.before-*.bak`、`.bak`／`.json.bak` 和对应 `.tmp` 变体，精确规则以迁移模块为准。不要在私人目录放置来源不明的同名备份。

新写入器的 `.<已知目标>.<32位小写十六进制编号>.tmp` 可能是中断留下的未提交密文。对应主配置有效时，迁移不尝试解密它，而是原样移入 `_private/_uncommitted/`，输出 `private_uncommitted_file_quarantined` 警告，并继续使用已校验主配置。隔离目录不再次扫描，也不自动删除。

这项恢复只适用于明确的新写入器命名：坏主配置、损坏的正式密文或历史备份仍会阻断启动；缺少有效主配置时不会自动拿临时文件顶替。移动隔离文件失败会保留原件并停止启动，以便处理文件锁、权限或磁盘问题后重试。

遇到 `settings_load_failed` 等启动错误时，先保存错误编号和日志位置，保留整个私人目录，检查运行账户是否正确及目录是否可写。不要反复清空设置、把部分密文当 JSON 修改，或将 `_uncommitted` 文件直接恢复为主配置。

若有同一账户、同一电脑上的完整密文备份，可在服务停止后恢复主配置并重新启动校验。确需更换账户且无法解密时，先将不可读主件及已知备份、残留临时文件保留到独立的私人备份位置，再移出迁移扫描范围，由新账户启动并重新填写；B 站登录需重新扫码。仅移走主文件可能仍因同目录坏备份阻断启动。

代码具备迁移能力不等于本机正式凭据已经迁移。实际状态取决于是否用新版成功启动及对应文件；整理文档不会启动迁移或修改凭据。

## 缓存检查点与版本

PDF 库替换不改变 HTTP、数据库、材料结构、`EXTRACTION_VERSION`、资料指纹、任务与缓存版本。已保存材料和笔记直接复用，不自动重新提取；已保存的 MinerU 批次、远端任务及完成结果也继续复用。“材料已保存、任务交接尚未完成”时，恢复仍依据原有材料映射与预分配任务编号去重。

旧 OCR 检查点从未完成页继续。若新旧图片编码使摘要不同，适配器读取已完成记录对应的页码和图片编号，建立当前图片摘要到旧缓存键的内存映射；已完成图片复用原识别结果，包括空结果和失败结果，不重新 OCR。映射不增加图片数量额度，不改写旧记录摘要；完成页全部齐备时直接返回保存记录。原件和旧检查点无需手工迁移。只有 PDF 恢复传入可选缓存键，其他格式继续按图片字节摘要缓存。

| 层次 | 复用范围 | 失配或删除的影响 |
|---|---|---|
| 原件去重 | 原件内容；可 OCR 文档还结合实际解析身份 | 不能仅用可编辑标题判断相同资料 |
| 已提取文档材料 | 已保存的来源块与文本 | 重新生成沿用原材料；解析修复不会自动重做历史内容 |
| 视频识别缓存 | 来源、识别配置与采样规则；语音和画面有各自签名 | 新规则不直接覆盖旧缓存，恢复按任务原配置读取 |
| 文档导入记录 | 源编号、解析批次、OCR 进度和材料／任务映射 | 删除可能丢失重启接续能力，不能当普通无用临时目录清空 |
| 生成检查点 | 本任务、输入、大纲、上下文、提示词及模型等身份 | 继续和重试复用兼容成功部分，新任务不直接复用旧总结 |
| 成功完整笔记 | 每份资料保留最近两份 | 旧版本淘汰同步移除其重点，不改变原件和识别材料 |

视频短哈希和文档完整哈希有不同的既有序列化规则，不能因为名称相同就替换算法。来源快照、生成流程版本和结果格式也分别校验。

成功后先在事务中登记检查点清理标志，再对本任务文件执行改名与删除；失败保留标志，Worker 定期补清，重启后也可继续。该过程不改笔记正文、完成时间或版本顺序；识别缓存不属于这次检查点清理。

## 备份与迁移项目目录

1. 正常停止服务，等待任务和下载清理完成；不在数据库持续写入时随意复制单个 SQLite 文件。
2. 将整个 `data/` 作为一组备份，包含存在的数据库伴随文件、原件、材料、导入记录和私人设置。需要保留模型时另备份 `models/`，并妥善保存 `.env`。
3. 保留相关日志用于排查。本机文档归档和实验产物按需要单独备份，它们不由 Git 自动保存。
4. 在目标位置恢复整套资料，再检查启动路径。加密凭据跨账户／电脑可能不可用，按上节重新配置，不承诺复制密文即可跨机使用。

`models` 通常可重新准备，前端构建可重新生成，但丢失原件、来源材料、数据库或唯一备份不能靠重建 dist 恢复。资料目录不要与源码清理操作混用。

## Git 与本地文件边界

README 和五篇专题与源码一起维护。archive、PROJECT_CONTEXT、现有 AGENTS、用户资料、模型、日志、私人配置、构建和测试报告沿用对应忽略规则；AGENTS 文件本身保持原样。

忽略只表示不会自动纳入 Git，不表示文件已被备份或可以删除。不要用强制添加整个目录的方式发布项目；提交前检查实际文件清单。第三方依赖及其许可分别见依赖清单与各依赖的官方说明。
